# 選手個人ページタブ別URL付与計画書

目的: 投手・野手の選手個人ページに、既存タブごとのURLを付与する。ただし対象は **既に存在するページのURL付与だけ** とし、UI・見出し・タブ位置・タブ文言・表示内容を変更しない。

## 基本方針

- 個人ページの見た目は 2026年7月1日時点を正とする
- 既存のページ内タブUIを維持する
- 見出しは既存の選手名表示を維持する
- URLを開いたときは、対応する既存タブが選択された状態で同じページUIを表示する
- SEO都合で見出しやレイアウトを変えない
- 新しい独立ページを増やさない
- 既存URLは壊さず、旧URLから新URLへの読み替えだけを追加する

## 過去事案を踏まえた禁止事項

過去に個人ページが壊れた主因は、URL付与と同時に UI 構造・見出し生成・ページ分割まで変更したことだった。今回の計画では以下を禁止する。

- タブ追加と同時に見出しを `詳細成績 2026` などへ差し替えること
- タブ追加と同時にページ上部のUI構成を変更すること
- 既存のページ内タブを消して、URL別の別UIへ置き換えること
- タブ本文を別コンポーネントへ強制分離して、表示条件を変えること
- 既存タブの順番、文言、位置、色、余白を変えること

## 対象URL設計

前提: ベースURLは `/players/{slug}` とする。例: `/players/teruaki-sato`

### 投手

既存の4面をURLで直接開けるようにする。

- 基本成績: `/players/{slug}`
- 球種情報: `/players/{slug}/pitch`
- 状況別: `/players/{slug}/situation`
- 対戦成績: `/players/{slug}/matchup`

### 野手

既存の5面をURLで直接開けるようにする。

- 基本成績: `/players/{slug}`
- 球種情報: `/players/{slug}/pitch`
- 状況別: `/players/{slug}/situation`
- 対戦成績: `/players/{slug}/matchup`
- 球団別: `/players/{slug}/vs-team`

### 捕手

既存の6面をURLで直接開けるようにする。

- 基本成績: `/players/{slug}`
- 球種情報: `/players/{slug}/pitch`
- 状況別: `/players/{slug}/situation`
- 対戦成績: `/players/{slug}/matchup`
- 球団別: `/players/{slug}/vs-team`
- 捕手成績: `/players/{slug}/catcher`

## Phase 1

目的: 現在の個人ページで、URLとタブ状態の責務を切り分ける。

作業内容:

- 現在のページ内タブ状態を棚卸しする
- 投手・野手・捕手で、どのタブが既存UIの正なのかを固定する
- 既存の `slug` 解決とタブ状態の切替点を整理する
- 旧 `tab` クエリや暫定URLがあれば一覧化する

完了条件:

- 投手4、野手5、捕手6のURL対応表が確定している
- どのURLがどの既存タブを開くか説明できる

## Phase 2

目的: URLセグメントと既存タブ状態の対応だけを定義する。

作業内容:

- `basic` はベースURLに割り当てる
- `pitch` `situation` `matchup` `vs-team` `catcher` を内部タブ状態へ割り当てる
- 既存の `pitch-types` `splits` `advanced` など、旧来と競合する名前は新設しないか、互換用の読み替えだけに限定する
- 無効なセグメントはベースURLへ戻す

完了条件:

- URLセグメントから既存タブ状態へ一意に解決できる
- URL解決だけで見出しや本文分岐を変えていない

## Phase 3

目的: サーバー側ルーティングで新URLを受けられるようにする。

作業内容:

- `/players/[playerId]/[[...rest]]` で上記セグメントを受理する
- 既存の `slug` 解決をそのまま使う
- 過去の互換URLがあれば新URLへ正規化する
- ただし正規化はURLだけに留め、表示コンポーネントは同一のままにする

完了条件:

- URLを直打ちしても404にならない
- 表示されるUIは従来の個人ページと一致する

## Phase 4

目的: クライアント側で、URL初期表示時に既存タブを選択状態へ同期する。

作業内容:

- `pitch` なら既存の球種情報タブを開く
- `situation` なら既存の状況別タブを開く
- `matchup` なら既存の対戦成績タブを開く
- `vs-team` なら既存の球団別タブを開く
- `catcher` なら既存の捕手成績タブを開く
- URLに合わせてタブ状態を初期化するだけに留める
- タブ本文の描画関数や見出し文言を差し替えない

完了条件:

- URL直打ちで正しい既存タブが開く
- タブクリック時と同じ表示結果になる

## Phase 5

目的: タブクリック時にURLも同期する。ただし既存UIは変えない。

作業内容:

- 既存タブの `onClick` 時に shallow 相当でURLを更新する
- 既存のタブ色、位置、アニメーション、見出し、本文は変更しない
- ベースタブへ戻ったときは `/players/{slug}` に戻す

完了条件:

- タブ操作でURLが変わる
- 見た目は操作前後で同一

## Phase 6

目的: 既存導線を新URLへ読み替える。

作業内容:

- サイト内リンクで、タブを直接開く必要がある箇所だけ新URLを使う
- ただし通常の選手名リンクはベースURLを維持する
- sitemap や site-map は新URLを追加してもよいが、見出し差し替え前提のSEO分岐は入れない

完了条件:

- サイト内からタブ別URLへ自然に遷移できる
- 通常の個人ページ導線は壊れていない

## Phase 7

目的: 見出しとUIが壊れていないことを重点確認する。

確認項目:

- 選手名見出しが従来のまま
- 今季 / 通算 の上段タブ位置が従来のまま
- 今季内サブタブの文言、順番、位置、色が従来のまま
- 投手、野手、捕手で本文内容が従来のまま
- URL直打ち時だけ対象タブが選ばれる
- ベースURLを開いたときは従来どおりの初期表示

完了条件:

- UI差分が URL 表示以外に存在しない
- 2026年7月1日時点の個人ページUIとの差分を説明できる

## Phase 8

目的: 再発防止策を実装前チェックに組み込む。

必須チェック:

- `displayName` 見出しを動的に書き換えていない
- 既存のページ内サブタブを無効化していない
- 新しいURL用の別タブバーを追加していない
- UI変更を伴うコミットとURL対応コミットを混在させていない
- 本番確認は投手・野手・捕手の3系統で別々に行う

運用ルール:

- URL対応のPRでは「UI変更なし」を先頭に明記する
- 画面確認は `/players/{slug}` とタブ別URLの両方で行う
- 問題発生時はURL同期処理だけを切り戻せるよう、UI本体とは分離して変更する

## 実装順の要約

- Phase 1: 対応表固定
- Phase 2: URLセグメント定義
- Phase 3: ルーティング受理
- Phase 4: 初期タブ同期
- Phase 5: タブクリック時URL同期
- Phase 6: サイト内導線更新
- Phase 7: UI無変化確認
- Phase 8: 再発防止運用固定
