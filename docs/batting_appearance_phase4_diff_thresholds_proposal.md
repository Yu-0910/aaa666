# Phase 4 差分許容・Go/No-Go 案（メモ v0.1）

親計画: `docs/plan_batting_derived_appearance_stats_primary_phases.md`（Phase 4）

**草案です。** 実データのスモーク結果を見て数値・分類は更新する。確定版は承認記録とセットで `batting_appearance_phase4_gate_checklist.md` の完了行に要約を残す。

---

## 1. 目的

- **Phase 6 一括再生成**の前に、「旧（zip 無効）」と「新（zip 有効）」の派生差分について **何を許し、何で止めるか** を事前に合意する。
- 許容は **指標ごと** と **試合／選手の例外リスト** の両方で持つ。

---

## 2. 分類: 試合・打者単位

| 区分 | 定義（案） | 扱い（案） |
|------|------------|------------|
| **G0** | ゴールデン試合で、`N===M` かつ zip が期待どおり | 差分ゼロを目標。非ゼロなら **No-Go**（修正優先） |
| **G1** | `N===M` だが文言正規化のみの差（表記ゆれ） | 差分を **一覧化して許容**可能（承認要） |
| **G2** | `N !== M`（計画どおり zip 無効・ログフォールバック） | 旧新で **打席結果が変わらない**ことを確認すれば差分小を許容しうる |
| **G3** | `N !== M` かつ表とログの順序ズレが疑われる難例 | **例外リスト**に gameId を登録し、当該試合は閾値外／手動レビュー必須 |
| **G4** | Phase10・canonical の欠損など **データ品質**起因 | 本計画の範囲外として **別チケット**／Phase **6** 延期理由にできる |

## 3. 数値閾値（案・初版）

以下は **スモーク範囲内**（例: 数十試合・1 年度）を想定。**確定値はスモーク後に埋める。**

| 対象 | 指標（例） | 許容案 | No-Go 案 |
|------|------------|--------|----------|
| Phase 11 打撃派生 | 打数・安打・本塁打のいずれかが変わる **選手数** | **≤ ___ 人**（空欄: 未設定） | 想定外の大量変化、または規定打席境界でのランキング順位の意図しない逆転が多数 |
| Phase 11 | 1 選手あたりの **安打差分の絶対値** | **≤ ___**（通常 0 か 1 に収まる想定） | 複数安打の系統的ズレ |
| 対左右（vs_hand） | R/L の打数が変わる **選手数** | **≤ ___ 人** | 名簿・投手 ID 異常と併発する場合は G4 を疑う |
| ランキング（Phase 12） | 規定未満で順位のみ変化 | 文書化のうえ **許容可** | 規定以上の行が入替・数値破綻 |

**デフォルト方針（案）**: zip が **張っていない**試合（`zip=0` かつ旧新で打席結果解決が同一）では、Phase 11 の **合計値差分はゼロ**であることをゲートに含める。

## 4. Go / No-Go（意思決定）

| 判定 | 条件（案） |
|------|------------|
| **Go** | チェックリスト A〜F 完了。G3 例外リストが文書化され、G0〜G2 の閾値を満たす。承認者が署名または Issue で Approve。 |
| **条件付き Go** | 特定年度のみ先送り、例外試合をランキングから除外する等の **運用回避**を文書化し承認。 |
| **No-Go** | G0 不正、G4 がスモークの一定割合を超える、ロールバック検証失敗、必須 `validate:*` の失敗。 |

## 6. 確定方針（② Phase11 vs 出場行合算・③ Phase3 N≠M コホート）

計画書の趣旨: **打席ごとの結果**は出場成績と一球ログを **検算のうえで切替**し、足りない部分はログで補う。`N !== M` のとき zip を張らずログ側へフォールバックするのは **仕様どおり**（G2）。Phase 11 は **canonical 上の打席列**から集計する派生であり、出場成績 **HTML 行を縦に足しただけ**の合計と一致することを求めない。

### ② `validate:batting-phase11-vs-batting-lines` が赤い件

- **決定**: 本 Phase 4（出場成績主軸）ゲートの **必須合格条件に含めない**。  
- **理由**: 二系統は **定義が異なる**（打席列ベース vs 表行ベース）。赤は **参考**（差の監視用）。表と Phase11 を一致させる別作業に回す。  
- ゲート表記: `docs/batting_appearance_phase4_gate_checklist.md` の「ゲート対象外」表に列挙。

### ③ Phase3 スキャン「118 試合中 113 が N≠M」

- **決定**: この比率だけをもって **Phase 6 を No-Go にしない**。コホートの多くは **G2（zip 無効・フォールバック）** とみなし **一括で許容**してよい。  
- **A3 の実務**: **118 試合すべて**を許容表に gameId 単位で書き分けることは **必須としない**。必須なのは **ゴールデン試合**、**難例として追う試合**、**プロダクトが指定した試合**だけを、許容リスト／修正キュー（G3）に載せること。  
- **理由**: 計画は「一致するときだけ出場文言を正とする」であり、「全試合で表とログの件数が一致すること」を前提にしていない。
