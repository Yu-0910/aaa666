# 2026ドラフト候補ソート page phase 9 番付表の生成

## 実行内容

phase 9 として、`/draft-candidate-sort/result` で localStorage の `banzukeResult` を読み込み、番付表として表示する処理を実装した。

## 追加ファイル

- `app/draft-candidate-sort/result/DraftCandidateSortResult.tsx`

## 更新ファイル

- `app/draft-candidate-sort/result/page.tsx`

## 表示内容

番付表では以下を表示する。

- 東
- 番付
- 西
- 候補者名
- 所属
- ポジション

候補者データがまだ存在しないIDの場合は、IDを代替表示する。

## 番付ラベル

`banzukeResult` は phase 7 の `resultBuilder` で生成する。

ラベルは以下。

- 1組目: 横綱
- 2組目: 大関
- 3組目: 関脇
- 4組目: 小結
- 5組目以降: 前頭1、前頭2、前頭3

## 表示しない情報

番付表には以下を表示しない。

- 評価
- 各スポーツ紙名
- 各紙の印
- 判定根拠
- 参照元
- 詳細リンク
- 外部リンク

`未評価` という文言は、ユーザーが `両方知らない` を押した候補を後で確認するための機能名として扱う。候補者の評価ランクや外部データ上の評価ではない。

## 検証結果

2026-09-17 に以下を確認した。

- `/draft-candidate-sort/result`: 200
- 番付ラベルとして `横綱`、`大関`、`関脇`、`小結`、`前頭1` が生成される
- 結果ページに番付表コンポーネントが接続されている
