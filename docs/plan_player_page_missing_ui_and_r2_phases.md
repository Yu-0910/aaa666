# 投手個人ページランキングUI・野手球団別タブ復旧計画

目的: 投手個人ページのランキングUI不足と、野手個人ページの球団別タブが本番で見えない問題を切り分け、git実装とR2反映のどちらを直すべきか明確にしたうえで復旧する。

## Phase 1 — 現状確認

目的: 問題を「UIが存在しない」「UIはあるが表示条件で隠れている」「UIはあるがR2データがない」の3つに分ける。

確認対象:

- 投手個人ページの今季サブタブ定義
- 野手個人ページの今季サブタブ定義
- 野手球団別タブの表示条件
- 個人ページ派生データのR2キー
- 本番で表示されない具体的な選手URL

完了条件:

- 投手ランキングUIがgit上に未実装か確認できている
- 野手球団別タブがgit上に存在するか確認できている
- R2不足で消える範囲と、git不足で消える範囲を説明できる

## Phase 2 — 投手個人ページのランキングUI設計

目的: Phase 1で「投手ランキングUIはgit上に未実装」と確認できたため、投手個人ページに追加するランキングタブの仕様を確定する。

確定方針:

- 「今季の成績」内に `ランキング` サブタブを追加する
- 既存の投手ランキングJSONを参照する
- 参照先はローカル `public/data/rankings/pitching/{year}/{league}`、本番R2 `data/rankings/pitching/{year}/{league}` に揃える
- 個人ページ内では対象選手の主要指標順位を表示する
- 対象選手がランキングJSONにいない場合でもタブ自体は出し、空状態を表示する
- 既存のグローバル導線 `成績一覧` は残すが、個人ページ内ランキングUIの代替とは扱わない

対象指標:

- まずはTOP投手グリッドで既に使っている主要9指標に限定する
- 1段目: `防御率`, `勝利`, `K-BB％`
- 2段目: `K％`, `HLD`, `Ｓ`
- 3段目: `WHIP`, `QS率`, `P/IP`
- 新しいランキング計算は追加しない

行の照合仕様:

- 対象選手IDは個人ページ側の `rosterMatchedNpbId` または `playerIdNormalized` を使う
- ランキングJSON行は `npbPlayerId` を優先して照合する
- `npbPlayerId` がない場合のみ `playerId` で照合する
- CL/PLのリーグが判定できる場合は該当リーグだけ読む
- リーグ判定できない場合はCL/PL両方を読み、最初に一致した行を採用する

表示仕様:

- 各指標カードには `順位`, `指標名`, `値`, `リーグ`, `球団` を表示する
- 値はランキングJSONの該当キーを使い、既存ランキング表示のフォーマット規則に寄せる
- 取得失敗または対象行なしの場合はカードを消さず、`-` またはデータなし表示にする
- タブ自体はR2データの有無で消さない

実装候補:

- `PlayerPagePitcherRankingBody` を新規コンポーネントとして追加する
- 既存の `loadPitchingRankingJson` をクライアント側で利用する
- 指標リストは `lib/topPagePitching2026Grid.ts` の `PITCHING_TOP_2026_GRID_METRICS` に揃える
- 行型は既存の `RankingRow` とランキングJSONの素の行を扱えるようにする

完了条件:

- 追加するUIの位置、ラベル、データ参照先、空状態が確定している
- 新規データ生成なしで実装できる範囲が明確になっている

## Phase 3 — 投手ランキングUIのgit実装

目的: 投手個人ページにランキングUIを追加する。

作業内容:

- 投手今季サブタブに `ランキング` を追加する
- `PlayerPageClient` にランキングタブの描画分岐を追加する
- 投手ランキングJSONから対象選手の順位を引ける表示コンポーネントを追加する
- リーグ判定は既存の名簿・所属情報を優先し、判定できない場合はCL/PL両方を探索する
- R2データがない場合でもタブ自体は消さず、データなし表示にする
- 既存の `基本成績 / 球種情報 / 状況別 / 対戦成績` の挙動を変えない

完了条件:

- 投手個人ページでランキングタブが常にUIとして確認できる
- R2データがある場合は順位が表示される
- R2データがない場合は空状態が表示される

## Phase 4 — 野手球団別タブの表示条件確認

目的: Phase 1で「野手球団別タブUIはgit上に存在」と確認できたため、本番で消える原因を表示条件・本番反映・R2反映に分けて特定する。

確認対象:

- `showFielderSeasonPilotUi` が対象選手で true になるか
- 名簿照合が成功しているか
- 対象選手が投手扱いまたは profile-only 扱いになっていないか
- 数値ID / NPB ID / Yahoo ID の解決が正しいか
- 最新gitが本番にデプロイされているか
- 対象URLで `今季の成績` が表示される状態か
- 対象URLで `基本成績 / 球種情報 / 状況別 / 対戦成績` までは出ているか

完了条件:

- タブが出ない原因が、表示条件・本番未反映・選手ID解決・R2データ不足のどれかに分類できている
- R2不足だけでタブ自体が消える、という誤判定を除外できている

## Phase 5 — 野手球団別タブのgit修正

目的: Phase 4で表示条件またはID解決が原因と判定された場合だけ、野手として扱うべき選手で球団別タブが消えないようにする。

作業内容:

- 必要なら `showFielderSeasonPilotUi` の条件を修正する
- 名簿照合やID解決の不足があれば補完する
- データがない場合もタブ自体は表示し、空状態を表示する
- 既存の対戦成績・基本成績・球種情報・状況別タブの挙動を壊さない
- Phase 4で本番未反映またはR2不足のみと判定された場合、このPhaseのgit修正は実施しない

完了条件:

- 対象の野手個人ページで `球団別` タブが表示される
- R2データがない場合でもタブが消えない
- git修正が不要な場合は、その理由が記録されている

## Phase 6 — 個人ページ派生データのR2確認

目的: UI修正後、または野手側でUIが存在することを確認した後に、中身が空になる原因がR2不足かどうか確認する。

前提:

- Phase 1時点でローカルには以下が存在する
- 投手個人派生: `_data/derived/player_season_pitching_poc/2026`
- 野手球団別派生: `_data/derived/player_batter_vs_team_count_pitch_types/2026`
- 投手ランキング: `public/data/rankings/pitching/2026`
- 野手ランキング: `public/data/rankings/2026`

確認対象:

- 投手個人ページ派生: `data/derived/player_season_pitching_poc/{year}/npb_{id}.json`
- 野手球団別配球: `data/derived/player_batter_vs_team_count_pitch_types/{year}/yahoo_{id}.json`
- 投手ランキング: `data/rankings/pitching/{year}/{league}/{metric}.json`
- 野手ランキング: `data/rankings/{year}/{league}/{metric}.json`

完了条件:

- 対象選手の必要JSONがR2に存在するか確認できている
- 存在しないJSONが一覧化されている
- ローカルにはあるがR2にないものと、ローカルにもないものを分けて記録できている

## Phase 7 — 必要データの生成

目的: R2に上げるべきローカルデータが対象選手単位で不足している場合だけ、必要な派生JSONとランキングJSONを生成する。

実行判断:

- Phase 1時点ではカテゴリ単位のローカルJSONは存在するため、原則として生成は不要
- 対象選手の個別JSONがローカルにもない場合だけ生成する
- ローカルにはありR2にだけない場合は、このPhaseをスキップしてPhase 8へ進む

作業内容:

- 野手球団別配球が不足している場合は `phase33:build:batter-vs-team-count-pitch-types` を実行する
- 投手個人派生が不足している場合は投手個人派生の生成処理を実行する
- ランキングJSONが不足している場合はランキング再生成を実行する
- 生成後にローカルの存在確認を行う

完了条件:

- R2アップロード対象のJSONがローカルに揃っている
- 生成をスキップした場合は、ローカルに対象JSONがあることを確認できている

## Phase 8 — R2反映

目的: 本番UIが参照するR2に、必要なランキングJSONと個人ページ派生JSONを反映する。

作業内容:

- ランキングJSONをR2へアップロードする
- 個人ページ派生JSONをR2へアップロードする
- 必要に応じて2026年分だけに絞って反映する
- git実装が必要な投手ランキングUIは、R2反映とは別に本番デプロイする
- R2反映だけで投手ランキングUIが出るとは扱わない

推奨コマンド:

- ランキングのみ: `npm run display:r2:upload:2026`
- 個人ページ派生のみ: `npm run display:r2:upload:derived:2026`
- 両方: `npm run display:r2:upload:all:2026`

完了条件:

- R2上に必要な `data/rankings/...` と `data/derived/...` が存在する
- gitデプロイが必要な変更と、R2アップロードだけで反映される変更が分かれている

## Phase 9 — 本番確認

目的: git実装とR2反映が本番で正しく効いているか確認する。

確認内容:

- 投手個人ページにランキングUIが出る
- 投手ランキングUIに対象選手の順位が出る
- 野手個人ページに球団別タブが出る
- 野手球団別タブに球団別配球が出る
- データがない選手でもタブ自体は消えず、空状態が出る
- 投手ランキングUIが出ない場合はgitデプロイを疑う
- 野手球団別タブは出るが中身が空の場合はR2派生データを疑う

完了条件:

- 対象URLで投手ランキングUIと野手球団別タブの表示が確認できている

## Phase 10 — 再発防止

目的: 今後、git側UI不足とR2データ不足を混同しないようにする。

作業内容:

- 個人ページUIのタブ存在を確認する軽量テストを追加する
- R2に必要な `data/derived/...` があるか確認する検証手順を追加する
- データなし時にタブを消さず、空状態を出す方針を明文化する
- 運用手順に「gitデプロイ」と「R2アップロード」は別作業であることを追記する

完了条件:

- UI不足とデータ不足を別々に検知できる
- 本番反映時の確認手順が文書化されている
